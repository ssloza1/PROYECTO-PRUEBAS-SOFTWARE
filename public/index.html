Valores Límite & Equivalencia

Técnicas de Pruebas Implementadas en el Proyecto

1. Análisis de Valores Límite (Boundary Value Analysis - BVA) TÉCNICA DE CAJA NEGRA

Se probaron las fronteras de stock (ej. stock disponible = 5; vender 5 es válido y deja stock en 0; vender 6 lanza error de stock insuficiente). En cálculo de subtotales: cantidad = 0 lanza excepción; cantidad = 1 es el límite válido inferior; precio = 0 es admitido; precio negativo lanza error.

2. Partición de Equivalencia (Equivalence Partitioning - EP) TÉCNICA DE CAJA NEGRA

Clases de equivalencia válidas e inválidas para estados de producto: AGOTADO (≤ 0), CRITICO (1 a stock_minimo), y NORMAL (> stock_minimo). Para validación de clientes: cliente activo puede comprar, cliente inactivo es rechazado automáticamente por regla de negocio.

3. Pruebas de Integración y Transacciones Atómicas (ACID) INTEGRACIÓN

Verificación del ciclo transaccional BEGIN → INSERT cabecera → INSERT detalle → UPDATE stock → COMMIT. Si ocurre una falla en cualquier ítem, se dispara ROLLBACK para evitar inconsistencia de datos en Supabase. Al anular una venta (/api/ventas/:id/anular), se repone de forma íntegra el stock restado previamente.

Comandos para Ejecutar las Pruebas en Terminal:

# Ejecutar todas las pruebas (Unitarias e Integración)
npm test

# Ejecutar únicamente pruebas unitarias con mocks rápidos
npm run test:unit

# Ejecutar pruebas de integración contra la API REST
npm run test:integration

# Generar reporte de cobertura de código
npm run test:coverage
